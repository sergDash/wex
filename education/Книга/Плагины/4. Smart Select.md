# Wex Select: справочник

Компонент для Wex в одном файле: аналог select2. Выпадающий список с поиском, одиночным и множественным выбором, своим внешним видом строки результата и действием по клику.
Два режима на одном движке: **select** хранит значение (для форм), **search** запускает действие (переход по ссылке или ваш обработчик) и ничего не хранит.

Пометка `(не проверено)` стоит у того, что написано по коду, но ещё не прогонялось в настоящем браузере. Всё остальное прогонялось в jsdom на реальном `dist/wex.js`: 74 автоматические проверки (одиночный выбор, мультивыбор, поиск по URL, пагинация, клавиатура, демо-страница целиком). Вёрстка, реальные размеры и скролл в jsdom не считаются, поэтому всё, что про пиксели, помечено отдельно.

<a id="quickstart"></a>

## Быстрый старт

```html
<script>window.Quas = { AutoDarkMode: false };</script>
<script src="https://cdn.jsdelivr.net/gh/wemmbley/quas@master/Source/Quas.js"></script> <!-- jQuery раньше Wex -->
<script src="https://cdn.jsdelivr.net/gh/wemmbley/wex@3.x/dist/wex.min.js"></script>
<script src="https://cdn.jsdelivr.net/gh/wemmbley/wex@3.x/dist/plugins/wex-smart-select.js"></script>                                              <!-- после Wex -->

<template id="app">
  <Country name="country" placeholder="Страна" @change="onCountry"></Country>
</template>

<script>
createSelect({
  tag: 'Country',
  source: [
    { id: 'ua', label: 'Ukraine' },
    { id: 'pl', label: 'Poland' },
    { id: 'de', label: 'Germany' }
  ]
})

$('#app')
  .state({})
  .method('onCountry', state => function (row) { console.log(row) })   // { id: 'ua', label: 'Ukraine' } или null
  .mount()
</script>
```

| Принцип | Что значит |
|---|---|
| Фабрика, а не плагин | `createSelect()` **не** передаётся в `.plugin()`. Она создаёт компонент, регистрирует его глобально под именем из `tag` и возвращает View |
| Один вызов, одна конфигурация | Рендерер, источник данных и поведение зашиты в конфиг. Нужны два разных поиска, значит два вызова с разными `tag` |
| Вызывать до `.mount()` | Так же, как `createDataTable` |
| Свой state у каждого экземпляра | На странице можно держать сколько угодно `<Country>`, выбор у них независимый |
| Теги требуют закрытия | `<Country></Country>`, не `<Country/>` |

Без опции `tag` фабрика просто вернёт View, зарегистрировать его можно самому: `component('Country', createSelect({...}))`.

<a id="props"></a>

## Тег и props

```html
<Category name="category_id" placeholder="Категории" :value="form.categories" :disabled="locked" @change="onCats"></Category>
```

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | строка | `''` | Имя скрытого поля формы ([см. раздел](#forms)). Только в режиме `select` |
| `placeholder` | строка | `Select…` / `Search…` | Подсказка в пустом поле. Умолчание зависит от режима и задаётся в `texts` |
| `:value` | строка, объект или массив | `null` | Начальный выбор: строка данных `{ id, label }` либо массив таких строк |
| `:disabled` | булево | `false` | Блокирует ввод и открытие |

| Правило | Пояснение |
|---|---|
| Только объявленные props | Wex принимает лишь те props, что есть в state компонента. Опечатка в имени тихо игнорируется |
| `value` читается один раз | При монтировании. Менять выбор снаружи потом нельзя, это известное ограничение Wex ([см. раздел](#pitfalls)) |
| `value` это строки данных, не id | В форме хранится только `id`, но показать «Обувь» вместо `5` плагин сам не может. Сервер отдаёт и id, и текст сразу |
| JSON-строка | Если `value` пришёл строкой, плагин попробует разобрать её как JSON. Удобно из Blade (не проверено в браузере) |
| Одиночный режим | Из массива берётся только первый элемент |
| `:disabled` | Передавайте булево через `:`. Строка `disabled="false"` для Wex непустая, то есть истина |

Голое значение вроде `[5, 8]` не подойдёт: без текста подписи показать нечего, плагин напишет предупреждение в консоль и пропустит элемент.

<a id="events"></a>

## События

```html
<Category @select="onSelect" @change="onCats" @open="onOpen" @close="onClose"></Category>
```

```js
.method('onSelect', state => function (row) { ... })
.method('onCats',   state => function (rows) { ... })
```

| Событие | Аргумент | Когда |
|---|---|---|
| `@select` | строка данных | На **каждый** выбор строки (клик, Enter), даже если `onPick` отменил действие |
| `@change` | значение | Когда значение реально изменилось: выбор, снятие, чип `×`, Backspace, очистка, `api.select/deselect` |
| `@open` | нет | Список открылся |
| `@close` | нет | Список закрылся |

Значение в `@change`: при `multiple` массив строк, иначе одна строка или `null`. Это копии, менять их безопасно.

Порядок при клике по строке: `onPick` → `@select` → (если не отменено) `@change` → `@close`.
В режиме `search` `@change` не вызывается никогда: значения там нет.

Обработчики вешаются как всегда: `.method('имя', state => function (аргумент) {...})` у **родителя**.

<a id="modes"></a>

## Режимы select и search

| | `mode: 'select'` (по умолчанию) | `mode: 'search'` |
|---|---|---|
| Назначение | Выбрать значение для формы | Найти и перейти / выполнить действие |
| Хранит значение | да | нет |
| В закрытом поле | Подпись выбранного (одиночный) или чипы (мульти) | То, что набрано |
| Минимум символов | `0`: список открывается сразу | `1`: пока меньше, показывает подсказку |
| При выборе строки | Ставит значение, закрывается (одиночный) | Вызывает `onPick`, закрывается, идёт по `href` |
| Текст после закрытия | Сбрасывается | Остаётся в поле |
| Кнопка `×` | Очищает значение | Очищает текст |
| `multiple` | доступен | всегда `false` |

Одиночный `select` показывает выбранное как текст в поле. Когда список открыт, поле работает как строка поиска, а текущая подпись остаётся подсказкой (`placeholder`). При открытии активной (подсвеченной) строкой становится выбранная.

Список открывается: кликом по полю, набором текста, стрелками ↑↓. Просто фокус его **не** открывает.

<a id="multiple"></a>

## Мультивыбор

```js
createSelect({ tag: 'Category', multiple: true, max: 4, source: '/api/categories' })
```

| Что | Как работает |
|---|---|
| Чипы | Выбранные значения показываются чипами в поле. `×` на чипе снимает значение |
| Клик по выбранной строке | Снимает выбор (переключатель) |
| Backspace | В пустом поле удаляет последний чип |
| Список после выбора | Не закрывается (`closeOnSelect` по умолчанию `false`) |
| Поисковый текст после выбора | Очищается и список перезагружается (`clearOnPick` по умолчанию `true`) |
| `max: 4` | Пятую строку выбрать нельзя, внизу списка подпись «Maximum 4 selected». `@change` при отказе не вызывается |
| Порядок значений | Как выбирались: сначала начальные, потом добавленные |
| Выбранные строки в списке | Подсвечены классом `selectedClass`, у них `aria-selected="true"` |

<a id="source"></a>

## Источники данных

От простого к сложному, все формы задаются одной опцией `source`.

### 1. Статический массив

```js
source: [{ id: 1, label: 'Shoes' }, { id: 2, label: 'Hats' }]
```

Фильтрация на клиенте: `label` содержит введённый текст без учёта регистра. Запросов нет, `debounce` равен `0`. Простые значения тоже годятся: `source: ['red', 'green']` превратится в `{ id: 'red', label: 'red' }` (только при строковых `key` и `label` без точки).
Своя фильтрация: `filter: (row, q) => boolean`, где `q` в нижнем регистре.

### 2. URL

```js
source: '/api/products?q={q}'     // {q} подставляется, значение кодируется
source: '/api/categories'         // нет {q}: допишется ?q=... или &q=...
```

| Деталь | Поведение |
|---|---|
| Метод | `GET` через `$wire.get(url)` |
| Имя параметра | Если в URL нет `{q}`, дописывается `q=`. Имя меняется опцией `queryParam` |
| Страница | При `pageSize > 0` подставляется `{page}` либо дописывается `page=`. Имя: `pageParam` |
| `debounce` | `250` мс по умолчанию |
| Устаревшие ответы | Запрос отменить нельзя, поэтому ответ **игнорируется**, если пользователь успел ввести новый текст или закрыть список |
| Ошибка | В списке «Failed to load», подробности в консоли |

### 3. Функция

```js
source: (q, { page, pageSize }) => fetch('/api?q=' + encodeURIComponent(q)).then(r => r.json())
```

Может вернуть массив, `{ items, more }`, `Promise` или jqXHR.

### 4. Объект

```js
source: { url: '/api/products?q={q}', minChars: 2, debounce: 300, pageSize: 10, results: 'payload.rows' }
```

Нужен ровно один из ключей `url`, `items` (массив) или `fetch` (функция). Любую из опций `minChars`, `debounce`, `pageSize`, `results`, `queryParam`, `pageParam`, `transport`, `filter` можно положить сюда: она перекроет одноимённую верхнеуровневую.

### Свой транспорт

```js
transport: url => myFetch(url)    // вместо $wire.get
```

Должен вернуть что-то из: `Promise`, jqXHR, цепочку `$wire` (`.done/.fail`) или готовое значение. Именно так подключается [фейковый сервер](#fake).

<a id="response"></a>

## Формат ответа

| Ответ сервера | Откуда берутся строки |
|---|---|
| Массив `[...]` | Он сам |
| `{ "items": [...] }` | `items` |
| `{ "data": [...] }` | `data` (формат Laravel Resource) |
| Любая другая форма | Путь через точку в опции `results`: `results: 'payload.rows'` |

Каждая строка должна быть объектом с полями, на которые указывают `key` и `label` (по умолчанию `id` и `label`). Другие поля (`image`, `description`, `url`) нужны только вашему рендереру и `href`.

Нужна ли следующая страница (`more`):

1. Если ответ-объект содержит булево поле `more`, берётся оно.
2. Иначе при `pageSize > 0`: пришло строк не меньше `pageSize`, значит есть ещё.
3. Иначе `false`.

Если ваши поля называются иначе: `key: 'sku'`, `label: 'name'`, либо функцией `label: row => row.first + ' ' + row.last`. Ключ используется для сравнения выбранных строк и должен быть **уникален**.

<a id="renderer"></a>

## Свой вид строки: рендерер

Рендерер это обычный Wex-компонент, ровно как `Thumb` в DataTable. Подключается опцией `item`.

```js
const ProductRow = $(`<template><div class="flex items-center gap-3">
  <img w-src="row.image" alt="" class="h-9 w-9 shrink-0 rounded object-cover">
  <div class="min-w-0">
    <div class="truncate">{{ row.label }}</div>
    <div class="truncate text-xs text-slate-500">{{ row.description }}</div>
  </div>
</div></template>`).state(() => ({ row: null, query: '', selected: false }))

createSelect({ tag: 'ProductSearch', mode: 'search', source: '/api/products?q={q}', item: ProductRow })
```

А для другого поиска достаточно другого рендерера, например, только заголовок:

```js
const TitleOnly = $(`<template><span>{{ row.label }}</span></template>`).state(() => ({ row: null }))
createSelect({ tag: 'DocSearch', mode: 'search', source: '/api/docs?q={q}', item: TitleOnly, href: r => r.url })
```

| Правило | Пояснение |
|---|---|
| `row` обязателен | Это строка данных. Без ключа `row` в state props будут проигнорированы |
| `query` по желанию | Текст, по которому получена выдача. Нужен для подсветки совпадения |
| `selected` по желанию | Была ли строка выбрана **в момент создания** |
| `active` не передаётся | Подсветку активной строки делает плагин классом на обёртке (`activeClass`), рендереру знать не нужно |
| State функцией | `.state(() => ({...}))`: рендерер создаётся много раз |
| Без рендерера | Выводится `label` текстом и `✓` у выбранной строки |
| Не вкладывайте `<a>` | Клик по строке обрабатывает плагин. Ссылка внутри сработает ещё и сама по себе |
| Один рендерер на несколько селектов | Можно, каждый `createSelect` регистрирует его под своим внутренним именем |

Строка пересоздаётся при каждой новой выдаче и при смене выбора, поэтому `query` и `selected` всегда актуальны на момент показа. Меняться «на лету» внутри уже показанной строки они не будут ([почему](#internals)). Если нужен чекбокс-галочка у выбранных, используйте `selected` внутри рендерера, он обновится при выборе.

<a id="pick"></a>

## Клик по строке: href и onPick

```js
createSelect({
  tag: 'ProductSearch', mode: 'search', source: '/api/products?q={q}',
  href: row => row.url,
  onPick(row, api, event) {
    if (!row.inStock) { api.close(); return false }      // false: не переходить по ссылке
  }
})
```

| Опция | Что делает |
|---|---|
| `href: row => url` | Только `search`. После выбора выполняется `location.assign(url)`. Ctrl или Cmd (клик или Enter) открывает в новой вкладке |
| `onPick(row, api, event)` | Вызывается на каждый выбор **до** действия по умолчанию. `this` внутри это View экземпляра. `return false` отменяет действие по умолчанию (переход или установку значения) |

Строка `row`, которую получает `onPick`, это копия: менять её безопасно. Показать «Товара нет в наличии» вместо перехода можно либо в `onPick`, либо в обработчике `@select` у родителя. Второй вариант срабатывает всегда, даже при `return false`.

### Объект api

| Член | Описание |
|---|---|
| `api.query` | Текущий текст в поле (только чтение) |
| `api.selected()` | Массив выбранных строк (копии) |
| `api.open()` / `api.close()` | Открыть или закрыть список |
| `api.clear()` | Сбросить значение и текст |
| `api.reload()` | Перезапросить выдачу с текущим текстом |
| `api.setQuery(текст)` | Подставить текст в поле (и перезапросить, если список открыт) |
| `api.select(row)` / `api.deselect(row)` | Выбрать или снять. Учитывают `max`, вызывают `@change`. Возвращают `true`, если что-то изменилось |
| `api.view` | View экземпляра |

Для показа модалки (когда она появится) логика такая: `api.close()`, затем вызов модалки, `return false`. Если модалка Bootstrap, то `$('#oos').modal('show')` (не проверено).

<a id="forms"></a>

## Формы и скрытые поля

Только режим `select` и только если задан `name`:

| Режим | Что отправится |
|---|---|
| Одиночный | Одно скрытое поле `name`. Пока ничего не выбрано, значение пустое (чтобы сброс дошёл до сервера) |
| Мульти | По полю `name[]` на каждое выбранное. Если `name` уже кончается на `]`, скобки не добавляются. Пока выбора нет, полей нет |

Значение поля это `key` строки (по умолчанию `id`).

Начальное значение из Blade:

```html
<Category name="category_id[]" value='@json($selected, JSON_HEX_APOS)'></Category>
```

`$selected` это массив вида `[{ "id": 5, "label": "Обувь" }]`. `JSON_HEX_APOS` нужен, чтобы апостроф в тексте не закрыл атрибут (не проверено в браузере). Mustache Wex в Blade экранируются как обычно: `@{{ }}`.

<a id="placement"></a>

## Позиционирование

```js
createSelect({ placement: 'auto', position: 'absolute', maxHeight: 280, minPanelWidth: 320, ... })
```

| Опция | Значения | Описание |
|---|---|---|
| `placement` | `auto` (умолчание), `top`, `bottom` | Куда раскрывать список. `auto` выбирает низ, если снизу есть место (хотя бы `min(maxHeight, 220)` px) или его больше, чем сверху |
| `position` | `absolute` (умолчание), `fixed` | Как рисовать панель |
| `maxHeight` | число px, `280` | Предел высоты списка. Реально берётся `min(maxHeight, свободное место)`, но не меньше 100 |
| `minPanelWidth` | число px, `0` | Минимальная ширина панели. По умолчанию она равна ширине поля |

Положение пересчитывается при открытии, при прокрутке страницы или любого её контейнера и при изменении размера окна (`auto` может перекинуть список вверх или вниз).

### absolute или fixed

| | `absolute` | `fixed` |
|---|---|---|
| Как рисуется | Внутри компонента, под полем или над ним | Координаты считаются от поля и ставятся панели на всё окно |
| Обрезается `overflow: hidden` у родителя | **да** | нет |
| Ширина | 100% поля, не меньше `minPanelWidth` | ширина поля, не меньше `minPanelWidth`; по горизонтали не выходит за окно (отступ 8px) |
| Подходит | Обычные формы | Карточки, таблицы, модалки с прокруткой |

Если у предка есть `transform`, `perspective`, `filter`, `backdrop-filter`, `will-change` с ними или `contain`, то `fixed` в браузере привязывается не к окну, а к этому предку (так работает CSS, это типично для анимированных модалок Bootstrap). Плагин находит такого предка и считает координаты от него (не проверено в браузере).

Размеры и места в jsdom не считаются, поэтому выбор `top`/`bottom` проверялся на подменённых координатах поля. Реальный запас места на экране нужно посмотреть глазами: прокрутите страницу так, чтобы поле оказалось у нижнего края.

<a id="paging"></a>

## Подгрузка при прокрутке

```js
createSelect({ tag: 'Category', source: '/api/categories', pageSize: 5 })
```

| Что | Как |
|---|---|
| Включение | `pageSize > 0` |
| Запрос | Первая страница уходит с `page=1`. Имя параметра: `pageParam`, либо `{page}` в URL, либо `ctx.page` в функции |
| Когда грузить дальше | Когда список прокручен почти до конца (остаток менее 48px) или стрелкой ↓ достигнуты последние 3 строки |
| Что с уже показанным | Новые строки добавляются в конец, старые остаются на месте |
| Конец | Пришло меньше `pageSize` строк (или `more: false`) |
| Новый текст в поле | Сбрасывает всё на первую страницу |
| Размер страницы | Плагин отправляет только номер страницы, **размер сервер знает сам**. `pageSize` в опции нужен только для определения конца |

Подгрузка сделана обычным обработчиком прокрутки, а не `w-lazy`: `w-lazy` сам грузит первую страницу при пустом списке и конфликтует с `debounce` и `minChars`.

<a id="keyboard"></a>

## Клавиатура и доступность

| Клавиша | Действие |
|---|---|
| ↓ / ↑ | Открывает список, если закрыт. Иначе двигает активную строку по кругу |
| PageDown / PageUp | Сдвиг на 5 строк, без зацикливания |
| Enter | Выбирает активную строку. Пока список открыт, отправку формы блокирует. `Ctrl+Enter` в `search` с `href` открывает ссылку в новой вкладке |
| Esc | Закрывает список и **останавливает всплытие**, поэтому не закроет модалку, внутри которой стоит поле |
| Tab | Закрывает список и отдаёт фокус дальше |
| Backspace | Только в мульти и только в пустом поле: удаляет последний чип |
| Home / End | Не перехватываются: остаются перемещением курсора в поле |

Мышь: наведение подсвечивает строку, клик выбирает, клик вне компонента закрывает, уход фокуса за пределы тоже закрывает. Нажатие на панель не уводит фокус из поля, поэтому клавиатура продолжает работать после клика.

ARIA (не проверено экранным диктором): у поля `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`; у панели `role="listbox"` и `aria-multiselectable`; у строк `role="option"` и `aria-selected`.

Активная строка при выборе стрелками прокручивается в видимую область автоматически (не проверено в браузере: в jsdom нет вёрстки).

## Тексты и локализация

Подписи по умолчанию английские, как в DataTable. Переопределяются частично:

```js
createSelect({
  tag: 'Country', source: [...],
  texts: {
    placeholderSelect: 'Выберите…', placeholderSearch: 'Поиск…',
    empty: 'Ничего не найдено', loading: 'Загрузка…', error: 'Не удалось загрузить',
    typeMore: n => 'Введите минимум ' + n + ' символа',
    max: n => 'Максимум ' + n,
    clear: 'Очистить', remove: 'Убрать'
  }
})
```

`typeMore` и `max` это функции от числа, остальное строки. `clear` и `remove` идут в `aria-label` кнопок.

<a id="server"></a>

## Что должен делать сервер

Минимум: принять `q` (и `page`, если нужна подгрузка), вернуть строки с полями `id` и `label`.

```php
// routes/api.php
Route::get('/api/products', function (Request $r) {
    $q = trim($r->query('q', ''));
    return ['data' => Product::query()
        ->when($q !== '', fn ($x) => $x->where('name', 'like', "%{$q}%"))
        ->limit(8)
        ->get()
        ->map(fn ($p) => [
            'id' => $p->id, 'label' => $p->name, 'description' => $p->category->name,
            'image' => $p->thumb_url, 'url' => route('product.show', $p), 'inStock' => $p->stock > 0,
        ])];
});
```

| Совет | Почему |
|---|---|
| Всегда ограничивайте выдачу | Поиск живой, строки идут в DOM |
| Экранируйте `%` и `_` в `LIKE`, если это важно | Иначе пользователь найдёт «всё» символом `%` |
| `inStock` и подобное считайте на сервере | Плагин ничего не знает о ваших правилах, `onPick` лишь реагирует на готовые поля |
| Для подгрузки отдавайте стабильный порядок | Иначе страницы будут пересекаться |

## Тестирование без сервера

Рядом с плагином лежит демо: `Select.html`, `FakeServer.js`, `Products.json` (41 товар), `Categories.json` (12 категорий). Картинки это SVG прямо внутри JSON, сеть не нужна.

```js
createSelect({
  tag: 'ProductSearch', mode: 'search',
  source: '/api/products?q={q}', transport: fakeServer, item: ProductRow, href: row => row.url
})
```

`fakeServer(url)` разбирает URL, читает JSON через `$wire.get('./Products.json')`, фильтрует и режет на страницы, отвечает с задержкой 150-600 мс. Эта задержка нарочно: видно «Loading…» и работает защита от устаревших ответов (введите быстро `wool`, затем `bag`: останутся результаты по `bag`).

| Нужно | Заметка |
|---|---|
| http-сервер | JSON читается через ajax, на `file://` не сработает: `python -m http.server` в корне репозитория |
| Путь к плагину | В демо `../../dist/wex-smart-select.js` |
| Каждый 4-й товар «не в наличии» | Для проверки `onPick` и плашки |
| Три сценария на странице | Поиск с `fixed`, мульти с подгрузкой и `max`, одиночный по массиву; ещё один одиночный у нижнего края для проверки `auto` |

<a id="internals"></a>

## Как это устроено внутри

Этот раздел объясняет, откуда берутся ограничения, и нужен, если плагин придётся дорабатывать.

| Факт | Следствие |
|---|---|
| Props дочернего компонента после монтирования не обновляются (известная проблема Wex) | Рендерер получает `row`, `query`, `selected` только при создании. Активную строку подсвечивает обёртка |
| Диффер сопоставляет строки по `id`, потом по `data-id`, остальное по индексу среди соседей | `id` и ключ строки включают версию выдачи и флаг выбора: так строка пересоздаётся и рендерер получает свежие props |
| Узлы без ключа сопоставляются по индексу | Чипы и скрытые поля лежат в своих контейнерах, чтобы число соседей у `<input>` не менялось: иначе диффер вставил бы новый `<input>`, а старый (с фокусом) удалил |
| `$wire.get()` возвращает цепочку `done/fail`, а не Promise | Плагин оборачивает её сам, для `transport` поддержаны все формы |
| Значение поля ввода выставляется напрямую | Привязка `w-value` у этого поля после выбора оставляла в нём старый набранный текст (причину не выяснял), поэтому `refresh()` пишет `input.value` сам |
| Состояние, которое не должно вызывать рендер (таймеры, счётчики запросов, слушатели `document`/`window`) | Лежит вне реактивного state, в карте по `uid` экземпляра. Слушатели снимаются при закрытии и при `$unmount` / `$destroy` |
| Производное состояние (чипы, строки, подписи, классы) | Считается вручную в `refresh()`, как в DataTable: во вложенных `w-for` внешняя переменная цикла может быть не видна |

<a id="pitfalls"></a>

## Частые ошибки и ограничения

| Проблема | Причина и что делать |
|---|---|
| Выбор не меняется после смены `:value` | `value` читается один раз при монтировании. Для сброса формы пересоздайте компонент (`w-if`) |
| Пропадают или сбрасываются все селекты на странице | `w-if` **перед** блоками с компонентами сдвигает индексы соседей, диффер пересоздаёт компоненты, они теряют состояние. Держите такой блок в DOM и прячьте через `style="display:..."` (так сделана плашка в демо) |
| Список обрезан рамкой карточки | `position: 'absolute'` внутри `overflow: hidden`. Поставьте `position: 'fixed'` |
| Рендерер не показывает `selected` / `query` | В его state нет таких ключей. Пропсы принимаются только по объявленным |
| Рендерер «залипает» на старых данных | Он создан без функции в `.state()`. Всегда `.state(() => ({...}))` |
| Не появляется картинка в строке | Для динамического `src` нужен `w-src`, а не `src="{{ ... }}"` |
| Ссылка внутри рендерера срабатывает дважды | Клик обрабатывает и плагин, и сама ссылка. Не вкладывайте `<a>` |
| `<Country/>` не работает | Тег компонента всегда с закрывающим: `<Country></Country>` |
| Два разных значения выглядят как одно | `key` не уникален. Выбор сравнивается по ключу |
| Пустая выдача при коротком тексте | Сработал `minChars`. В `search` он равен `1`, под полем будет подсказка |
| Новый текст, а список старый | Ответ на старый запрос пришёл позже. Он отбрасывается автоматически, но запрос сам не прерывается |
| В демо пустой список | JSON читается через ajax: нужен `http://`, не `file://` |
| Поле заблокировано, хотя указано `disabled="false"` | Без `:` приходит строка, а непустая строка для Wex истина. Передавайте булево через двоеточие: `:disabled="false"` |
