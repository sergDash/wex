# Wex DataTable: справочник

Плагин и компонент для Wex в одном файле: таблица с серверной пагинацией, сортировкой, фильтрами и поиском. Визуально аналог DataTable из PrimeVue, стили на Quas, тёмная тема через `dark:`.
Режим один: **серверный**. Таблица ничего не фильтрует и не сортирует сама, она собирает JSON-запрос, отправляет его и рисует ответ.

Пометка `(не проверено)` стоит у того, что написано по коду, но ещё не прогонялось в браузере.

## Быстрый старт

```html
<script>window.Quas = { AutoDarkMode: false };</script>
<script src="https://cdn.jsdelivr.net/gh/wemmbley/quas@master/Source/Quas.js"></script> <!-- jQuery раньше Wex -->
<script src="https://cdn.jsdelivr.net/gh/wemmbley/wex@3.x/dist/wex.min.js"></script>
<script src="https://cdn.jsdelivr.net/gh/wemmbley/wex@3.x/dist/plugins/wex-datatable.min.js"></script>                                  <!-- после Wex -->

<template id="app">
  <DataTable url="/api/products" title="Products" :columns="columns" @select="onSelect"></DataTable>
</template>

<script>
const dt = createDataTable({ perPageOptions: [10, 25, 50] })

$('#app')
  .state({
    columns: [
      { field: 'id',    label: 'ID',    type: 'number' },
      { field: 'name',  label: 'Name' },
      { field: 'price', label: 'Price', type: 'number' }
    ]
  })
  .method('onSelect', state => function (keys) { console.log(keys) })
  .plugin(dt)
  .mount()
</script>
```

| Принцип | Что значит |
|---|---|
| Плагин и компонент одновременно | `createDataTable()` регистрирует глобальный компонент и возвращает функцию для `.plugin()` |
| Только сервер | Любое изменение сортировки, фильтров, поиска, страницы или размера страницы приводит к новому запросу |
| Глобальные имена | Тег по умолчанию `<DataTable>`, меняется опцией `name`. Теги компонентов требуют явного закрытия |
| Роутер необязателен | Нет `$router`, значит URL не трогается вообще ([см. раздел](#router)) |

<a id="props"></a>

## Тег и props

```html
<DataTable url="/api/products" title="Products" :columns="columns" perPage="25" routeKey="p" @select="onSelect"></DataTable>
```

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `url` | строка | `''` | Адрес, на который уходит запрос |
| `title` | строка | `''` | Заголовок в панели над таблицей |
| `:columns` | массив | `[]` | Описание колонок ([см. раздел](#columns)) |
| `perPage` | число | опция `perPage` | Начальный размер страницы |
| `routeKey` | строка | опция `routeParam` | Ключ страницы в query. Нужен, если на странице несколько таблиц |
| `@select` | событие | нет | Вызывается при выборе строк, получает массив ключей |

Wex принимает только те props, которые уже есть в state компонента. Опечатка в имени тихо игнорируется.
Колонки должны лежать в **начальном** state родителя: читаются один раз при монтировании.

<a id="columns"></a>

## Колонки

```js
{ field: 'status', label: 'Status', type: 'text', renderer: 'StatusBadge', sortable: true, filterable: true }
```

| Поле | По умолчанию | Описание |
|---|---|---|
| `field` | обязателен | Ключ в строке данных. Он же уходит на сервер в `sort`, `filters`, `columns` |
| `label` | `field` | Заголовок |
| `type` | `'text'` | `text`, `number`, `date`, `boolean`. Определяет набор операторов, тип поля ввода и приведение значений |
| `renderer` | нет | Имя зарегистрированного рендерера. Без него выводится значение как текст |
| `sortable` | `true` | `false` убирает сортировку по колонке |
| `filterable` | `true` | `false` убирает иконку фильтра и колонку из списков «Add filter» |
| `virtual` | `false` | Колонка без данных (например, `Actions`). Не уходит в `columns`, не сортируется, не фильтруется |
| `operators` | из опций по `type` | Список операторов именно для этой колонки |
| `caseSensitive` | из опций | Регистрозависимость текстовых операторов для этой колонки |

Колонка `image` с рендерером `Thumb` обычно ставится как `sortable: false, filterable: false`. Колонка действий: `virtual: true`.

<a id="renderers"></a>

## Рендереры ячеек

Рендерер это обычный Wex-компонент. Регистрируется при инициализации: ключ становится и именем тега, и значением `renderer` в колонке.

```js
const StatusBadge = $(`<template><span class="rounded px-2 py-1 text-xs font-medium" w-class="{
  'bg-blue-100 text-blue-900': value==='Pending',
  'bg-green-100 text-green-900': value==='Delivered' }">{{ value }}</span></template>`)
  .state(() => ({ value: '', row: null }))          // value и row обязательны

const dt = createDataTable({ renderers: { StatusBadge } })
// колонка: { field: 'status', renderer: 'StatusBadge' }
```

| Правило | Пояснение |
|---|---|
| `value` и `row` в state | Таблица передаёт `:value` (значение ячейки) и `:row` (копия строки). Без этих ключей в state props будут проигнорированы |
| State функцией | `.state(() => ({...}))`: компонент создаётся много раз |
| Регистрация глобальная | Локальные компоненты не наследуются дочерними, поэтому рендереры ставятся через глобальный `component()` |
| Имя тега | Как в `renderers`. Регистр в HTML не важен, но пишите единообразно |
| Неизвестное имя | Если `renderer` указан, а компонент не зарегистрирован, ячейка останется пустой |
| Значение `undefined` | Для колонок без данных (`virtual`) в `value` приходит `''` |

Рендереры, которым нужны данные строки (кнопки действий), берут их из `row`.

<a id="options"></a>

## Опции createDataTable

Передаются один раз при инициализации плагина.

```js
const dt = createDataTable({
  perPage: 25,
  perPageOptions: [10, 25, 50],
  caseSensitive: false,
  operators: { number: ['equals', 'between', 'greater_than'] },
  response: { total: 'meta.total' }
})
```

| Опция | По умолчанию | Описание |
|---|---|---|
| `name` | `'DataTable'` | Имя тега |
| `perPage` | `15` | Размер страницы по умолчанию |
| `perPageOptions` | `[5, 10, 15, 25, 50]` | Варианты в списке Rows per page |
| `rowKey` | `'id'` | Поле-идентификатор строки: для выбора строк и `traceby`. Нет поля, берётся индекс |
| `routeParam` | `'page'` | Ключ страницы в query роутера |
| `caseSensitive` | `false` | Регистрозависимость текстовых операторов. Переопределяется на колонке |
| `match` | `'all'` | Как комбинировать условия: `all` (И) или `any` (ИЛИ). Уходит в `filters.match` |
| `multiSort` | `true` | Shift+клик добавляет поле к сортировке |
| `renderers` | `{}` | `{ Имя: WexView }` ([см. раздел](#renderers)) |
| `transport` | `$wire.post` | Своя отправка запроса ([см. раздел](#transport)) |
| `operators` | см. [операторы](#operators) | Доступные операторы по типу колонки |
| `operatorLabels` | `{}` | Подписи операторов, например `{ contains: 'содержит' }` |
| `request` | см. [запрос](#request) | Имена ключей запроса |
| `response` | см. [ответ](#response) | Пути к данным в ответе |

Объекты `request`, `response`, `operators`, `operatorLabels` сливаются с умолчаниями на один уровень: меняете один ключ, остальные остаются. Но `operators.number: [...]` заменяет список целиком.

<a id="operators"></a>

## Операторы фильтров

| Тип колонки | Операторы по умолчанию |
|---|---|
| `text` | `equals`, `not_equals`, `contains`, `not_contains`, `starts_with`, `ends_with`, `in`, `not_in`, `is_null`, `is_not_null`, `is_empty`, `is_not_empty` |
| `number` | `equals`, `not_equals`, `greater_than`, `less_than`, `greater_or_equal`, `less_or_equal`, `between`, `not_between`, `in`, `not_in`, `is_null`, `is_not_null` |
| `date` | `equals`, `not_equals`, `greater_than`, `less_than`, `greater_or_equal`, `less_or_equal`, `between`, `not_between`, `is_null`, `is_not_null` |
| `boolean` | `equals`, `not_equals`, `is_null`, `is_not_null` |

Что ожидается в `value`:

| Вид | Операторы | Форма `value` |
|---|---|---|
| Без значения | `is_null`, `is_not_null`, `is_empty`, `is_not_empty` | ключа `value` в условии нет |
| Два значения | `between`, `not_between` | массив ровно из двух элементов. Границы **включительные** |
| Список | `in`, `not_in` | массив. В поле вводится через запятую |
| Одно значение | остальные | скаляр |

`is_null` проверяет `NULL`, `is_empty` проверяет пустую строку `''`: это разные вещи.

Свой набор на колонку:

```js
{ field: 'status', operators: ['equals', 'not_equals', 'in', 'not_in'] }
```

Лишнее убирается через опцию `operators` (на все колонки типа) или `operators` на колонке (только на неё).

<a id="request"></a>

## Протокол запроса

Запрос уходит `POST` с JSON-телом ([транспорт](#transport)).

```json
{
  "page": 5,
  "per_page": 20,
  "sort": [
    { "field": "name", "dir": "asc" },
    { "field": "created_at", "dir": "desc" }
  ],
  "search": { "field": null, "value": "almanach" },
  "filters": {
    "match": "all",
    "items": [
      { "field": "title", "operator": "contains", "value": "almanach", "case_sensitive": false },
      { "field": "price", "operator": "between", "value": [1, 10] },
      { "field": "deleted_at", "operator": "is_null" }
    ]
  },
  "columns": ["id", "title", "price"]
}
```

| Ключ | Описание |
|---|---|
| `page`, `per_page` | Номер страницы с 1 и размер страницы |
| `sort` | Массив: порядок элементов это приоритет сортировки. Пустой массив, если сортировки нет |
| `search` | `null` или `{ field, value }`. `field: null` значит «по всем колонкам», список колонок для поиска определяет сервер |
| `filters.match` | `all` или `any` |
| `filters.items` | Условия. На одно поле можно несколько, например `price > 10` и `price < 2` |
| `case_sensitive` | Только у условий по колонкам типа `text` |
| `columns` | Поля, которые нужны клиенту: все колонки, кроме `virtual` |

Значения в `value` приведены по типу колонки: `number` это число, `boolean` это `true/false`, остальное строка (даты в `YYYY-MM-DD`).

Имена ключей меняются опцией `request`:

```js
createDataTable({ request: { perPage: 'limit', filters: 'where' } })
```

Любое изменение сортировки, фильтров, поиска и размера страницы **сбрасывает страницу на первую**.

<a id="response"></a>

## Протокол ответа

Стандарт: ответ Laravel `paginate()` (EloquentCollection).

```json
{
  "current_page": 1,
  "data": [ { "id": 1, "name": "Test one" } ],
  "from": 1,
  "to": 15,
  "last_page": 4,
  "per_page": 15,
  "total": 60
}
```

| Ключ по умолчанию | Что означает |
|---|---|
| `data` | Строки |
| `total` | Всего записей по текущим фильтрам |
| `current_page` | Страница, которую вернул сервер |
| `per_page` | Размер страницы |
| `last_page` | Последняя страница |
| `from`, `to` | Диапазон для надписи Showing … from … results. `null` читается как `0` |

Если сервер вернул другую страницу (например, запрошена 9, а есть 4), таблица принимает `current_page` из ответа.

Другой формат (API Resource с `meta`) настраивается без правки кода, пути пишутся через точку:

```js
createDataTable({
  response: { total: 'meta.total', page: 'meta.current_page', lastPage: 'meta.last_page', from: 'meta.from', to: 'meta.to', perPage: 'meta.per_page' }
})
```

Таблица добавляет к строкам служебные поля `_key` и `_cells`. Имена начинаются с `_`, избегайте их в своих данных.

<a id="transport"></a>

## Транспорт и тестирование без сервера

По умолчанию: `$wire.post(url, body)`.

Свой транспорт получает `(url, body)` и возвращает `jqXHR` или `Promise`:

```js
createDataTable({
  transport: (url, body) => $wire.post(url + '?v=2', body)
})
```

**Фейковый сервер** для разработки: транспорт, который читает статический JSON через `$wire` и сам считает фильтры, сортировку, поиск и пагинацию в формате Laravel `paginate()`.

```js
let cache = null
const loadAll = () => cache || (cache = new Promise(res => $wire.get('./products.json').done(res)))

createDataTable({
  transport: (url, body) => loadAll().then(all => { /* фильтры, сортировка, пагинация */ return result })
})
```

Полная реализация (все операторы, `search`, мультисортировка) лежит в `index.html` демо. В проде опцию `transport` просто убирают. Открывать демо нужно через локальный сервер: с `file://` браузер не даст прочитать `products.json`.

| Нюанс | Пояснение |
|---|---|
| Гонки | Если запросы идут один за другим, применяется только ответ последнего |
| Ошибка | При неудаче строки очищаются, выводится `Failed to load data` |
| Загрузка | Пока идёт запрос, тело таблицы затемняется |

<a id="ui"></a>

## Сортировка, фильтры, поиск в интерфейсе

| Элемент | Поведение |
|---|---|
| Клик по заголовку | `asc`, затем `desc`, затем сортировка снята |
| Shift + клик | Добавляет поле к текущей сортировке (если `multiSort`). Порядок добавления это приоритет |
| Иконка сортировки | Обе стрелки яркие, если сортировки нет. Активная стрелка яркая, вторая притушена |
| Иконка фильтра в колонке | Открывает панель **под этой колонкой** с уже выбранным полем. Если по колонке есть фильтр, иконка синяя |
| Кнопки справа сверху | Фильтр и поиск: панель открывается под кнопкой |
| Панели | Закрываются крестиком, Cancel или кликом вне панели. Повторный клик по той же иконке тоже закрывает |
| Active filters | Чипсы с условиями и поиском. Крестик убирает условие |
| Оператор | При смене колонки список операторов и тип поля ввода пересчитываются: `number` это числа, `date` это календарь, `boolean` это список true/false |
| Пустое значение | Фильтр с пустым значением (кроме `is_null` и подобных) не применяется |
| Нет данных | Под таблицей выводится `No results` или `Loading…` |

Позиция панели считается от карточки таблицы: левый край под колонкой, зажатый границами карточки. (не проверено на узких экранах)

## Выбор строк

Чекбокс в строке и чекбокс «выбрать все» (все строки **текущей страницы**).

```html
<DataTable ... @select="onSelect"></DataTable>
```

```js
.method('onSelect', state => function (keys) { console.log(keys) })   // ['1', '5', '12']
```

| Нюанс | Пояснение |
|---|---|
| Ключи строками | Это значения `rowKey`, приведённые к строке (`Object.keys`) |
| Между страницами | Выбор сохраняется при пагинации, сортировке и смене фильтров |
| «Выбрать все 1234» | Не реализовано: для этого на сервер нужно слать фильтр, а не id |

<a id="router"></a>

## Роутер и номер страницы

Если подключён роутер Wex, страница хранится в query: `#/products?page=5`.

```js
$('#app').state({...}).plugin(createRouter({ mode: 'hash', routes: { home: '/' } })).plugin(dt).mount()
```

| Ситуация | Что происходит |
|---|---|
| Монтирование | Номер страницы читается из `?page=`, иначе 1 |
| Клик по странице | Пишется `setParams({ page })`: добавляется запись в историю |
| Назад/вперёд в браузере | Событие `$route`: если страница в URL отличается, таблица грузит её |
| Сброс на первую страницу | После смены сортировки или фильтра `page=1` тоже пишется в URL |
| Несколько таблиц | У каждой свой `routeKey`, иначе они будут делить один `page` |
| **Роутера нет** | URL не читается и не пишется: доступ к роутеру ленивый, ошибок нет |

Порядок `.plugin(router)` и `.plugin(dt)` не важен. Фильтры и сортировка в URL **не** пишутся.

(не проверено: запись `page=1` в hash-режиме и поведение кнопки «Назад»)

<a id="theme"></a>

## Тёмная тема и Quas

Тема работает по классу `dark` на `<html>`, во всех элементах через `dark:`. Если тема переключается вручную, в Quas нужен `window.Quas = { AutoDarkMode: false }` до подключения `Quas.js` (см. справочник Quas, раздел «Тёмная тема»).

Все классы из набора Quas, ничего дополнительно подключать не нужно: `table`, `table-row`, `table-cell`, `table-header-group`, `table-row-group`, `align-middle`, `even:`, `hover:bg-*/50`, `accent-blue-500`.

**Почему таблица сделана на `div`.** Wex перерисовывает элемент с `w-for`, разбирая его HTML вне контекста таблицы, и браузер выбрасывает теги `<tr>`, `<td>`, `<th>` вместе с атрибутом `w-for`. Поэтому вся таблица построена на `div` с `display: table-*` и ролями `role="table|row|cell|columnheader|rowgroup"`.

| Что | Как |
|---|---|
| Подсветка сортировки, иконка фильтра, текущая страница, затемнение | Готовые строки классов, интерполируются в `class="… {{ … }}"`. Не `w-class` |
| Внешний вид | Рамка, шапка, футер и панели повторяют каркас: кастомизация через классы в шаблоне |

<a id="server"></a>

## Что должен делать сервер

Клиенту доверять нельзя: всё, что пришло в JSON, нужно проверять.

| Правило | Зачем |
|---|---|
| Белый список колонок для `sort`, `filters`, `search`, `columns` | Иначе через `field` можно добраться до любой колонки |
| Белый список операторов **на колонку** | У `boolean` нет смысла в `contains` |
| Приведение типов по колонке | `value` может прийти не того типа |
| Экранирование `%` и `_` в `LIKE` | Иначе `contains` превращается в шаблон |
| Верхний предел `per_page` | Защита от выгрузки всей таблицы |
| `between` включительный, `in` из массива | Формат задан контрактом ([операторы](#operators)) |
| `case_sensitive` учитывать только для текста | В MySQL это зависит от коллации колонки |
| `search.field: null` | Список колонок для глобального поиска задаёт сервер |
| `filters.match` | `all` это `AND`, `any` это `OR` |

<a id="pitfalls"></a>

## Частые ошибки и ограничения

| Симптом | Причина и решение |
|---|---|
| Таблица пустая, колонок нет | `columns` не лежит в начальном state родителя или prop назван не так: props вне state игнорируются |
| Ячейка пустая | `renderer` указан, а компонент не передан в `renderers` |
| Рендерер не получает данные | В его state нет `value` и `row` |
| `<DataTable/>` не работает | Теги компонентов закрываются явно: `<DataTable></DataTable>` |
| Нет сортировки по колонке | `sortable: false` или `virtual: true` |
| Фильтр по колонке недоступен | `filterable: false` или `virtual: true` |
| Не тот оператор в списке | Тип колонки не `text`, смотрите набор для типа или `operators` на колонке |
| Фильтры пропали после перезагрузки | Так задумано: в URL пишется только страница |
| Таблица не показывает `from`/`to` | Ответ не по формату `paginate()`: настройте `response` |
| Строки «прыгают» при загрузке | Нет уникального `rowKey` в данных |
| `w-for` на `tr/td/th` в своей разметке | Теги пропадают, используйте `div` с `display: table-*` |

<a id="missing"></a>

## Чего нет в v1

| Возможность | Статус |
|---|---|
| Клиентский режим (все данные сразу) | Не делали, только серверный |
| Фильтры и сортировка в URL | Только страница |
| Выбор «все по фильтру» | Нужен серверный контракт |
| `match: 'any'` в интерфейсе | Работает по опции, переключателя в панели нет |
| Видимость, порядок, ширина колонок | Нет |
| Группировка, агрегаты, экспорт | Нет |
| Курсорная пагинация | Нет |
| Редактирование ячеек, раскрытие строк | Нет |
| Вложенные группы условий (`{ match, items }` внутри `items`) | Формат запроса это допускает, интерфейса нет |
