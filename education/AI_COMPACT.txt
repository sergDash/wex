WEX 3 — ПАМЯТКА ДЛЯ ИИ (пиши код СТРОГО по ней)

Wex = реактивный шаблонный движок без сборки. Proxy-state + точечные эффекты (как Vue 3/Solid). НЕ Vue, НЕ React, НЕ Alpine: синтаксис свой.

================ 1. СКЕЛЕТ ================
<template id="app">
  <h1>{{ title }}</h1>
  <input w-bind="draft">
  <button w-on="click:add">+</button>
  <ul><li w-for="t in todos traceby t.id" w-class="{ done: t.done }">
    <input type="checkbox" w-bind="t.done"> {{ t.text }}
    <button w-on="click:remove(t.id)">x</button>
  </li></ul>
  <p w-if="!todos.length">Пусто</p>
</template>
<script type="module">
  import Wex from './wex/index.js'
  const app = Wex.$('#app').state(() => ({ title: 'Дела', draft: '', todos: [] }))
  app.fn('add', (state) => { state.todos.push({ id: Date.now(), text: state.draft, done: false }); state.draft = '' })
  app.fn('remove', (state, id) => { state.todos = state.todos.filter(t => t.id !== id) })
  app.mount()            // без аргумента: корень-<div> создаётся после <template>; или mount('#el')
</script>
Без $: import { view } ...; view('<p>{{n}}</p>', () => ({ n: 1 })).mount('#root'). view(source) = HTML-строка | '#селектор' | элемент.
Браузер: window.Wex, window.$ (мини-jQuery, если нет настоящего jQuery).
initState: ФУНКЦИЯ (предпочтительно) или объект; обязан вернуть объект. Нужные ключи объявляй сразу (пропы и реактивность работают только по существующим/добавленным через Proxy ключам).

================ 2. ШАБЛОН ================
{{ expr }} в тексте и атрибутах. Атрибут целиком "{{x}}": null/undefined -> атрибут удаляется. В тексте null/undefined печатаются как "null"/"undefined" — защищай (x ?? '' через выражение/w-if).
Выражения — ScopeX (angular-подобно, есть фильтры). Простые пути a.b.c читаются напрямую.
НЕЛЬЗЯ {{ }} в src/href/srcset (браузер уже запросит сырую строку) -> w-src="expr".

Директивы (значение = выражение, без {{ }}):
 w-if="e"                 ветка создаётся/уничтожается
 w-for="x in list" | "x, i in list" | "... traceby x.id" | w-key="x.id"
                          list = массив ИЛИ объект (i = ключ). ВСЕГДА давай ключ для списков, которые меняются.
                          w-for + w-if на одном теге: if считается на каждую строку.
 w-class="{ cls: cond }"  ключ может содержать несколько классов через пробел; статический class не трогает
 w-value="e"              один-way value
 w-bind="path"            two-way; ТОЛЬКО присваиваемый путь (draft, user.name, t.done). checkbox=boolean
 w-disabled / w-checked / w-selected = "e"
 w-id="e" (null убирает) | w-src="e" | w-html="e" (innerHTML через sanitizeSvg — не для недоверенного HTML)
 w-transition="opacity .25s"   fade in/out
 w-on="event:method" | "event:method(a, b)"   (методы вызываются как fn(state, a, b))
 <slot :prop="expr">fallback</slot>   один default-слот, без именованных
 <w-static>…</w-static>   рендер один раз, без подписок
ПРЕФИКСЫ ":" и "@" существуют ТОЛЬКО на тегах компонентов (:prop, @event). На обычных элементах :class, @click, v-if, x-on, onclick="{{}}" НЕ работают. Используй w-*.

Порядок обработки тега: w-for -> w-if -> slot -> компонент/w-static -> атрибуты+дети.

================ 3. МЕТОДЫ И СОБЫТИЯ ================
view.fn(name, function (state, ...params) { ... })   this = view. Регистрируй ДО/после mount — не важно.
Возврат из w-on метода: функция -> вызовется как fn.call(el, event) (карринг (state)=>(e)=>{}); внутри false => preventDefault+stopPropagation.
w-on: один слушатель на событие на корне view (делегирование); один обработчик на событие на элемент; focus/blur/mouseenter/mouseleave/scroll/load/error/toggle — только на самом target.
view.on('click', '.sel', (state) => (e) => {...})  — DOM-событие на корне. view.on('$mount', function (state) {...}) — lifecycle.
Lifecycle: $init(state) -> $render -> $mount ; $unmount ; $beforeDestroy ; $destroy ; $change(state, info, prevent) (склеено на микрозадачу; info={target,key,type}) ; $update(state, prevent) ; $clone(state, newView).
view API: mount, unmount (state сохраняется), destroy, state, root, fn, on/once/off, emit, update, hold/release, clone, find, component, directive, filter, plugin.
update(true) = перерисовать всё; update(fn) / update(obj) = мутация state; hold()...release() = батч без промежуточных перерисовок.

================ 4. РЕАКТИВНОСТЬ (как работает — ПИШИ С УЧЁТОМ) ================
- state = Proxy над plain-объектами/массивами, глубоко и лениво. Чтение внутри эффекта -> подписка на (объект, ключ). Запись -> эффект в очередь -> flush в МИКРОЗАДАЧЕ (DOM обновляется асинхронно; в тестах: await Promise.resolve() или Wex.__flush()).
- Реактивны: plain {} и [] (новые ключи, delete, push/splice/sort, length). НЕ реактивны: экземпляры классов, Date, Map, Set, DOM-узлы, функции, Object.freeze, внешние объекты (Chart.js…). Мутировал такой объект -> вызови view.update(true) (или config.autoForce = true).
- Геттеры внутри state НЕ отслеживают зависимости (this = сырой объект). Производные значения считай в выражении шаблона или кладёшь в поле и обновляешь в обработчике. Не делай `get total(){...}` в state.
- Выражение, не прочитавшее ничего реактивного (window.x, поле класса), НИКОГДА не обновится.
- Запись того же значения не триггерит. Эффект не будит сам себя.
- Заменить массив целиком (state.todos = state.todos.filter(...)) — нормально и идиоматично.
- Присвоение в w-for-строке: item.x = ... меняет объект; запись в имя item меняет только строку; запись в чужое имя идёт в state родителя.
- Объекты, переданные пропом, — ОДНА И ТА ЖЕ ссылка у родителя и ребёнка (мутация видна обоим). Нужна изоляция — копируй при передаче.

================ 5. КОМПОНЕНТЫ ================
Регистрация (имя -> lowercase, тег в шаблоне):
  const card = Wex.view('<div class="card"><h3>{{ title }}</h3><slot></slot><button w-on="click:rm">x</button></div>', () => ({ title: '' }))
  card.fn('rm', function (state) { this.emit('remove', state.title) })
  Wex.component('user-card', card)      // глобально; parentView.component(name, v) — локально (видят потомки)
  <user-card :title="u.name" @remove="drop(u.id)" kind="primary">слот</user-card>
ПРОПЫ:
  :user-name="expr" -> реактивно, ключ userName (kebab -> camelCase; в HTML атрибуты lowercase, camelCase писать нельзя)
  kind="primary"   -> статическая СТРОКА
  Проп попадёт в компонент ТОЛЬКО если ключ уже есть в его initState (case-insensitive). Нет ключа = проп молча потерян. (Исключение: remote-компонент без <script>.)
СОБЫТИЯ: ребёнок this.emit('name', a, b). Родитель @name="handler(args)":
  parent.fn('handler', (state, ...tplArgs) => (a, b) => { ... })   // КАРРИНГ: вернуть функцию, иначе аргументы emit пропадут
  Имя события case-insensitive (@my-event <-> emit('myEvent')). События с $ — локальные, наверх не идут.
Корень: view из строки/<template> -> хост-тег остаётся, шаблон внутри него. view из не-<template> элемента -> хост заменяется этим тегом (+data-hoist).
Каждый экземпляр = proto.clone(): объект-initState клонируется глубоко, функция вызывается заново.
Рекурсия: компонент может использовать сам себя (нужен w-if для выхода; maxDepth 50).
Поиск компонента: свои -> родительская цепочка -> глобальные.
REMOTE:
  Wex.component('x-chart', '/c/x-chart.html', { lazy: true })   // файл: <template>…</template> + <script type="module">export default (T) => { const v = T.state(() => ({...})); v.fn(...); return v }</script>
  В <script> импорты только АБСОЛЮТНЫЕ (блоб-URL); без <script> state открытый (пропы создают ключи). Wex.preloadComponent(url) — прогрев.

================ 6. ОБЩИЙ STATE, ПЛАГИНЫ, ФИЛЬТРЫ, ДИРЕКТИВЫ ================
shareState (общий реактивный store):
  const cart = shareState({ items: [] }, { onChange: (key, value) => {...}, drive: (update) => {...} })
  $('#a').state(cart); $('#b').state(cart)   // оба view читают/пишут один state
  onChange не снимается; после него глобально включается режим подписки на поддерево (чуть дороже чтение).
Плагин: view.plugin(function () { const { view } = this; return { $mount(state){…}, $change(state, info){…} } })  // state в теле = null до mount
Фильтры: Wex.filter('money', v => …) глобально; view.filter(...) локально.
Директива-атрибут (имя = точное имя атрибута; атрибут остаётся в DOM; значение НЕ интерполируется):
  Wex.directive('w-tooltip', { mounted($el, attrs, bag){ $el.attr('title', this.scope.parse(attrs['w-tooltip'])) }, updated($el, attrs, bag){…}, unmounted($el, bag){…} })
  Классическая: Wex.directive(name, compile($el, attrs), affect($el, attrs) /* может вернуть revoke() */)
  this.scope: parse(exp), assign(key, v), $new(locals), interpolate(str), filters. attrs = {имя: значение} всех атрибутов.
  affect/updated бегут на ЛЮБОЕ изменение state этого view (грубо). Для горячих путей — компонент.
  Регистрируй директивы ДО создания view (копируются в view при создании). Параметр priority игнорируется.
Асинхронный компонент: createAsyncComponent(() => import('./x.js')) — для compile/affect контекста с this.view; пока не загружен — null; потом view.update(true).

================ 7. Wex.$ (мини-jQuery) ================
Есть: выборка/обход (find, closest, parent, children, next, prev, siblings, eq, filter, not, is, each, map…), attr/prop/val/data/css/class-методы, html/text/append/prepend/after/before/remove/clone, on/one/off/trigger (делегирование, namespaces click.ns), $.ajax/get/getJSON/post (jqXHR: done/fail/always/then/abort), $.extend, $.each, $.fn расширяется. $.fn.state(init) / .vm(init) создают view из <template>.
НЕТ: animate/fadeIn, serialize и пр. Если нужен настоящий jQuery — подключи ДО Wex, он подхватится сам (или Wex.useJQuery($)).

================ 8. ЧЕК-ЛИСТ ПЕРЕД ОТВЕТОМ ================
[ ] События на обычных элементах — w-on="event:method", а не @click.
[ ] Для динамических списков есть traceby/w-key.
[ ] Все ключи state (и пропов компонента) объявлены в initState.
[ ] @event-обработчик в родителе возвращает функцию.
[ ] w-bind указывает на присваиваемый путь.
[ ] Нет геттеров в state; производное считается в шаблоне/обработчике.
[ ] Мутация не-plain объектов сопровождается view.update(true).
[ ] Нет {{ }} в src/href; нет v-/x-/:class на обычных тегах.
[ ] Директивы зарегистрированы до создания view; remote-скрипты с абсолютными импортами.
[ ] Строгая CSP: движок использует new Function (нужен unsafe-eval).
